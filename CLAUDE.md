## What this project is

A school management system for many schools on one install. One Laravel app serves its own
React pages through Inertia.js (no separate API). Roles: Super Admin, School Admin, Principal,
Teacher, Accountant, Librarian, Receptionist, Driver, Warden, Store Manager, Student, Parent.

Long-term direction: a Nigerian-first "Education OS" (three terms, continuous assessment,
WAEC-style report cards, Naira payments). The build checklist for that lives in the project's
shared files; Phase 1 (safety fixes) is finished. Phase 2 (terms, score/grade setup, stored term results, invoices, the payment ledger, scholarships, and moving old fee payments into invoices) is finished. Phase 3 is under way: admission inquiry → entrance exam/interview → offer → enrolment is done, year-end promotion (move up, repeat, graduate) and report cards (term and full year) are done too.

## Tech stack (what is really in the repo)

| Layer | What is used |
|---|---|
| Backend | Laravel 13, PHP (`composer.json` says ^8.3, but the lock file pulls Symfony 8 which needs PHP 8.4 — use 8.4) |
| Frontend | React 19 + TypeScript, Vite 8, Tailwind CSS 4 |
| Bridge | Inertia.js 3 (every page is rendered through it) |
| UI | shadcn-style components (Base UI) in `resources/js/components` |
| Client state | Zustand — three small stores (`useAuthStore`, `useUIStore`, `useAttendanceStore`) |
| Forms | react-hook-form + zod; charts with recharts |
| Login | **Supabase checks the password** (`app/Services/SupabaseAuthService.php`); Laravel then decides what the person may do |
| Permissions | Spatie laravel-permission (roles + permissions), Spatie laravel-activitylog (audit trail) |
| Database | Supabase Postgres in production; SQLite for local development and tests |
| Files | Laravel Storage. Disks: `local`, `public`, `supabase` (S3 style), and `private` (documents) |
| PDF | barryvdh/laravel-dompdf, generated inside the web request. QR codes on certificates: chillerlan/php-qrcode (PNG, no outside service) |
| Queue / cache / sessions | Database drivers. `QUEUE_CONNECTION=sync` by default (jobs run inside the request). The `Procfile` starts `queue:work`; set `QUEUE_CONNECTION=database` in production to use it |
| Hosting | **cPanel** (the live site). Every merge to `main` deploys itself through `.github/workflows/deploy.yml`: it builds the front end and uploads `public/build`, then on the server resets the code to `main`, runs `composer install`, `migrate --force`, the `RolePermissionSeeder`, `demo:fill` and the caches. Nobody needs to run commands by hand. `railway.json`, `Procfile` and `vercel.json` are left over from earlier attempts |
| Tests | PHPUnit 12 (`php artisan test`) and Vitest + Testing Library (`npm test`; files in `resources/js/tests/`, config in `vitest.config.ts`). `.github/workflows/tests.yml` runs every test (PHP 8.4, SQLite, after building the front end) on each pull request, and `deploy.yml` runs it first and deploys only if it passes. The front-end tests cover the small helpers (money and position formatting, comment blanks, topic matching, the permission hook) and the shared page pieces; add a test next to any helper or shared component you write. `tests/e2e` holds browser checks (see below) |

**Not in this project (despite older docs):** Laravel 11, `app/Modules/*` folders, Redis,
Horizon, Sanctum, a full `/api/v1` REST layer (only the small read-only `/api/school` described under Developer kit), Stripe, 2FA, PestPHP,
Playwright, a mobile/PWA app, and a real SMS provider.

### Words used on screen (keep them the same everywhere)

- **Test** = something students sit on the computer ("Computer Tests", students see "My Tests"). **Exam paper** = the printed paper ("Printed Papers"). **Class Test Marks** = the older screen at `/school/exams` where one number is typed per student, subject and exam. Scores that count on the report card are **Term Results**.
- **Fees** is what parents and students call money owed; staff work in **Invoices**.
- **Arms** (never "Sections") for the parts of a class. A section inside a test or exam paper is a real section and keeps its name.
- **Announcements** = posts to a group; **Messages** = person to person; **Notifications** = automatic alerts about your own work.

## Rules for every session

1. **Read the module spec** in `requirements/modules/` first, but treat it as the goal; check the code for what exists.
2. **Every table that belongs to a school** has an indexed `school_id` (soft deletes on major tables) and its model uses `BelongsToSchool`. A test (`TenantCoverageTest`) fails if a new model with `school_id` skips the rule. Only four models are allowed to skip it (listed with reasons in that test).
3. **Every route under `/school` needs a `permission:` check** in `routes/web.php`. A test (`RoutePermissionTest`) fails if you add one without it. Pick the permission from `RolePermissionSeeder`; add a new permission there if none fits, and tell the user to re-run the seeder on deploy.
4. **Super Admin** passes every permission check (`Gate::before` in `AppServiceProvider`).
5. **Audit trail:** fee payments, marks, payroll and users are logged automatically; every log entry is stamped with the school. Role changes are logged by hand where they happen. Never log passwords.
6. **Inertia first:** pages get their data from the controller, not from a separate API call.
7. **No N+1 queries:** eager load with `with()`/`load()`. Computed values on `Mark` (`percentage`, `is_pass`, `total_marks`) need the `subject` relation loaded.
8. **TypeScript types** for page props live in `resources/js/Types/`. Avoid `any`.
9. **Zustand only for truly global state.** Local state stays in `useState`.
10. **Security defaults:** Eloquent only (no raw SQL); no `dangerouslySetInnerHTML`; validate uploads (type + size); uploaded documents go on the `private` disk and are served through a route that checks the person's school and permission. Pictures (logos, stamps, signatures, student photos) are stored with `App\Support\ImageShrinker::store`, which makes big JPEG/PNG files smaller first (max side 600px, 128px for favicons) and leaves small ones and other types untouched; upload limits for pictures are 10 MB so phone photos are accepted and then shrunk. The report card and certificate design pages preview unsaved choices and unsaved pictures through the `*.try` routes (a real form post, nothing stored, shown in an in-page preview), which the demo read-only guard lets through.
11. **Slow work:** PDF, imports and message blasts currently run inside the request or the stub job. Moving them to the queue is Phase 4 work; do not pretend it is done.
12. **Brand:** the product is called **Adino School Systems** (company: Adino Systems). It is shown as a text wordmark, "Adino" in bold sans (the same family as the page around it) with "School Systems" small underneath (`Wordmark` in `resources/js/components/layout/Logo.tsx`; `resources/views/partials/wordmark*.blade.php` for pages made with Blade); there is no logo picture. Public school websites end with "School Software by Adino Systems" (the nine footers in `resources/views/website/footers`); inside the app every page ends with "Powered by Adino Systems" (`AppLayout.tsx`). The webhook headers keep their old `X-SchoolRuns-*` names so existing integrations do not break.
13. **Keep this file true.** If you change the stack, add a module or fix a caveat above, update the table.

## Running things

```bash
composer install            # needs PHP 8.4 (see above)
npm install && npm run build
cp .env.example .env && php artisan key:generate
php artisan migrate --seed
php artisan test            # PHPUnit; uses in-memory SQLite and a built-in test app key
```

There is no `npm run type-check` and no lint script yet.

### Right-answer tests and browser checks

- `tests/Feature/Correctness` checks that figures are RIGHT, with expected values worked out by hand (fee balances to the kobo, part payments, scholarships, instalment splits, admission numbers, enrolment, sign-in and account switch-off, cross-school ids). Add a case here whenever a feature handles money or records.
- `tests/e2e` (see its README) drives the real app in Chromium as each role: `npm run build && npm run e2e` (or `-- --phase 1`). It uses a throw-away database, prints only the problems, and compares on-screen and stored values with hand-written expected answers. Phase 1 (money and people) is done; later phases are added as `phaseN.mjs`.
- Every plain `exists:table,column` validation rule is school-limited and ignores deleted rows automatically (`App\Support\TenantValidator`, registered in `AppServiceProvider`), so a form can never accept another school's id. Rules that already name `school_id` are left as written. `unique` rules are NOT changed.
- A suspended or inactive account cannot sign in and is signed out on its next click (`EnsureAccountActive`, `LoginController`). School admins cannot delete, switch off or change the role of their own account, nor remove the last working school admin.

### Safety-net tests (`tests/Feature/Security`)

School separation (models and by-id access), route permissions per role, user-account
permissions, login throttle, demo-login flag, private documents, GPS token, audit trail,
and the academic report. Run them before and after any change to routes, models or permissions.
`tests/Feature/CalculationsTest.php` checks grade and fee-balance sums at the edges (decimal scores on a boundary, kobo payments, rounding); `FeeLedgerTest` and `LegacyFeeImportTest` cover invoices and the copy from old records.
